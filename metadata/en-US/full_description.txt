An Android dashboard app for Zigbee2MQTT, built to replace closed-source apps. No cloud account required and no lock-in - the app talks directly to your own MQTT broker, and your whole configuration is either one plain JSON file you can export and re-import or auto-configure settings stored in MQTT.

<b>Optional online service:</b> the "Import via code" button on the Add Broker screen uses sync.odiousapps.com, a credential relay run by the developer. If you use it, you log in to an account on that site and pick a saved credential, and the broker's hostname, username and password are passed back to the app through that server. It is entirely optional - nothing is sent unless you tap the button and agree to continue - and brokers can always be entered by hand or imported from a file instead. The relay's server code is free software (Unlicense), published in the <a href="https://github.com/evilbunny2008/MX3Launcher/tree/main/website">MX3Launcher repository under website/</a>.

<b>Features:</b>
<ul>
<li>Groups of clusters, each cluster grouping the related tiles for one physical device (sensor readings, toggles/buttons) under a shared name</li>
<li>Sensor tiles with configurable decimal places, units, and an optional ideal min/max range that colours the tile red/green/blue when out of range</li>
<li>Toggle tiles reflecting live device state (not just the last command sent), and momentary button tiles for one-shot commands like a blind motor's STOP</li>
<li>Presence/occupancy sensor tiles - recognises both Zigbee2MQTT's "occupancy" and "presence" conventions, shown as "Detected"/"Clear" with a tinted icon rather than a raw true/false</li>
<li>Drag-and-drop reordering for groups, clusters within a group, and panels within a cluster (long-press to start dragging) - group reordering and renaming both happen directly on the dashboard via each group's own header, no separate screen needed</li>
<li>Groups can be collapsed/expanded, and deleted along with their panels</li>
<li>New-device and new-cluster prompts (see Auto-configure below) show as banners on the dashboard as well as system notifications</li>
<li>Sensor panels for any field in the device's regular state payload</li>
<li>Toggle and momentary-button controls (a control without an <tt>off_payload</tt> is treated as a single-press button rather than an on/off switch)</li>
<li>Per-field decimal places, custom ordering within and across clusters, and splitting one physical device's fields across multiple clusters</li>
<li>A manual reorder of auto-configured panels/clusters republishes an updated, retained <tt>/app</tt> message reflecting the new arrangement, so the device's own config stays in sync rather than being silently reverted on its next update</li>
<li>Watches every incoming MQTT payload, across every topic, for a <tt>"smoke": true</tt> field - no per-device registration needed</li>
<li>A live, filterable log of every MQTT message across all configured brokers - useful for debugging payloads and topic structures without a separate MQTT client</li>
<li>Export/import the whole configuration, or just the brokers list on its own (for moving connection details between devices without touching groups or panels), as a single gzip-compressed JSON file</li>
<li>A restore can replace the whole configuration, or - independently of how the file was originally exported - merge in just its brokers (matched by id: updates existing ones, adds new ones, leaves the rest of your setup untouched)</li>
<li>Full-configuration exports can optionally be encrypted (AES-256-GCM) using one of your broker's own passwords, rather than a separate password to remember - restoring auto-detects an encrypted file and prompts for the password before decrypting</li>
<li>Publish/restore a backup via a retained MQTT message instead, for moving configuration between devices without a file transfer - since that path never includes brokers in the backup at all, restoring from it always preserves whatever brokers are already configured on this device rather than needing to import them separately</li>
<li>Multiple brokers, each over TCP, SSL, WS, or WSS (including self-signed certificates)</li>
<li>A persistent background connection (optional, toggle in Settings) keeps data fresh even when the app isn't open - useful mainly for live updates while backgrounded, since MQTT topics are typically retained anyway</li>
<li>Manual sensor discovery, scanning a broker's traffic for numeric fields to help build panels for devices that don't publish their own <tt>/app</tt> config - launched per-broker (from that broker's row in Settings > Brokers), since you may only want to scan one specific broker rather than every one at once</li>
</ul>
